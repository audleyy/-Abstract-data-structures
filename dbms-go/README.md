# Структуры данных и интерфейс на Go

Проект содержит перенос пяти структур из присланного C++: массив, односвязный список, двусвязный список, очередь и стек. Красно-чёрного дерева и команд TINSERT/TDEL/TGET здесь нет.

## Сборка

Нужен Go 1.22 или новее. Зависимостей сторонних библиотек нет.

```bash
go build -o dbms .
go test ./...
```

Запуск из папки с go.mod:

```bash
./dbms --file file.data --query 'MPUSH numbers 10'
```

Для Windows сборка: `go build -o dbms.exe .`.

Исходные алгоритмы находятся в array.go, forwardList.go, list.go, queue.go и stack.go. Их имена функций сохранены: initArray, pushIndex, pushBack, get, remove, replace, length, destroy, print; addToHead, addToTail, addAfter, addBefore, findNode, deleteHead, deleteTail, deleteBefore, deleteAfter, deleteCurrent, printRegular, printReverse, printIndex; addTail, addHead, delHead, delTail, delAfter, delBefore; initQueue, enqueue, dequeue; initStack, isEmpty, push, pop.

Названия типов Array, Node, List, Queue и Stack и названия полей data, size, value, next, prev, head, tail также сохранены. Разные Node разделены пакетами dynamic_array, singly_linked_list, doubly_linked_list, queue и stack.

## Почему добавлены interface.go и Execute

В Go имя с маленькой буквы недоступно из другого пакета. Переименовать pushBack в PushBack означало бы нарушить требование о точном нейминге.

Поэтому исходные функции оставлены строчными и находятся в своих пакетах. В interface.go добавлена одна экспортируемая функция Execute: main вызывает её, а она вызывает исходные функции внутри своего пакета. Это новая служебная обёртка, не переименование исходного кода.

Execute получает команду, два числовых аргумента, признак обратной печати и сохранённые значения. Возвращает новые значения, ответ, признак изменения и ошибку. В каждом запуске восстанавливается только выбранная структура.

## Отличия языка Go от C++

- int* массива представлен срезом []int. Массив по-прежнему реализован вручную: при pushIndex, pushBack и remove выделяется новый срез через make и элементы переносятся циклами. Операции контейнера не заменены вызовами append.
- Node*& представлен **Node: изменение *head меняет голову списка у вызывающей функции.
- Array& представлен *Array.
- nullptr представлен nil, new Node — созданием &Node{...}.
- delete и delete[] в Go отсутствуют. Недоступные объекты освобождает сборщик мусора. Поэтому удаляются связи, а destroy массива обнуляет data и size.
- Локальные переменные, которые в C++ нужны только для delete, убраны, если в Go они больше не используются.
- int имеет размер, зависящий от платформы Go; он не обязательно совпадает с размером int конкретного компилятора C++.
- Числа в интерфейсе разбираются через strconv.Atoi, вывод — через fmt.

Это перенос алгоритмов и перестановок указателей. Побитовую эквивалентность модели памяти C++ обеспечить нельзя, особенно для ошибочных обращений к удалённым узлам: в Go нет ручного освобождения таких объектов.

## Точность переноса и сохранённые ошибки исходника

Поскольку было запрошено перенести реализацию в точности, известные ошибки исходных функций намеренно не исправлены.

1. **pushIndex массива запрещает index == size.** Вставка в конец и в пустой массив не выполняется. Интерфейс возвращает ошибку вместо успешного ответа. Добавление в конец следует выполнять через MPUSH.
2. **findNode двусвязного списка не проверяет последний узел.** LSEARCH последнего значения возвращает -1. Прямой вызов findNode с nil приводит к panic; интерфейс отдельно обрабатывает пустой список и возвращает -1.
3. **delAfter двусвязного списка неверно обновляет prev у следующего узла**, если удаляемый элемент не хвост. Эта ошибка сохранена в исходном алгоритме.
4. **delBefore двусвязного списка неверно обновляет next у предыдущего узла**, если удаляемый элемент не голова. Поэтому LDELBEFORE для внутреннего узла может вывести OK, но не убрать значение из сохранённой прямой цепочки.
5. Исходные функции вставки рядом с узлом, удаления и printIndex предполагают корректные указатели и индексы. Интерфейс проверяет выбранный индекс и существование соседа до их вызова, но не переписывает сами функции.
6. printReverse односвязного списка остаётся рекурсивной, как в C++; для очень длинного списка это требует глубокой рекурсии.

Перенесённая версия printReverse двусвязного списка использует tail/prev — именно ту версию, которая была в последнем присланном коде. В самих функциях printReverse нет завершающего перевода строки; обёртка добавляет его для консольного запроса.

Тесты отдельно фиксируют исходную проверку массива и пропуск хвоста при поиске: это тесты точности переноса, а не утверждение об отсутствии ошибок исходного алгоритма.

## Формат запуска

```text
./dbms --file путь --query 'КОМАНДА имя [числа]'
```

Ключи принимаются в указанном порядке. Один запуск выполняет один запрос. Запрос передаётся одним аргументом в кавычках.

Имена чувствительны к регистру и не содержат пробелов. Все элементы — int. Индексы начинаются с нуля. Первые буквы команд: M — массив, F — односвязный список, L — двусвязный список, Q — очередь, S — стек. PRINT — общее исключение.

## Команды

### Массив

| Команда | Действие |
|---|---|
| MPUSH name value | Добавить в конец |
| MPUSHINDEX name index value | Вставить перед существующим индексом; index < size |
| MGET name index | Прочитать элемент |
| MDEL name index | Удалить элемент |
| MSET name index value | Заменить значение |
| MLEN name | Получить длину |

### Односвязный список

| Команда | Действие |
|---|---|
| FPUSH name value | Добавить в конец |
| FPUSHHEAD name value | Добавить в начало |
| FPUSHBEFORE name index value | Добавить перед узлом |
| FPUSHAFTER name index value | Добавить после узла |
| FGET name index | Прочитать элемент |
| FSEARCH name value | Найти индекс первого вхождения либо -1 |
| FDEL name index | Удалить элемент |
| FDELHEAD name | Удалить голову |
| FDELTAIL name | Удалить хвост |
| FDELBEFORE name index | Удалить предыдущий элемент |
| FDELAFTER name index | Удалить следующий элемент |

### Двусвязный список

| Команда | Действие |
|---|---|
| LPUSH name value | Добавить в конец |
| LPUSHHEAD name value | Добавить в начало |
| LPUSHBEFORE name index value | Добавить перед узлом |
| LPUSHAFTER name index value | Добавить после узла |
| LGET name index | Прочитать элемент |
| LSEARCH name value | Поиск через исходную findNode с пропуском хвоста |
| LDEL name index | Удалить элемент |
| LDELHEAD name | Удалить голову |
| LDELTAIL name | Удалить хвост |
| LDELBEFORE name index | Вызвать исходную delBefore, включая её ошибку |
| LDELAFTER name index | Вызвать исходную delAfter, включая её ошибку |

### Очередь и стек

| Команда | Действие |
|---|---|
| QPUSH name value | Добавить в очередь |
| QPOP name | Прочитать и удалить первый элемент |
| SPUSH name value | Добавить на вершину |
| SPOP name | Прочитать и удалить вершину |
| SISEMPTY name | Проверить пустоту существующего стека |

### Печать

```text
PRINT name
PRINT name REVERSE
```

REVERSE разрешён только для списков. Всего поддерживается 34 команды, считая PRINT одной командой с необязательным аргументом.

Добавление создаёт отсутствующее имя. Но MPUSHINDEX на отсутствующем имени всё равно завершается ошибкой из-за исходного запрета вставки в пустой массив. Другие операции требуют существующей структуры.

Индекс BEFORE/AFTER относится к списку до операции. Перед головой и после хвоста нет соседа, поэтому соответствующее удаление отклоняется.

Добавления и MSET выводят переданное значение. QPOP/SPOP — удалённое. Другие изменения — OK. SISEMPTY выводит TRUE/FALSE. Поиск — индекс или -1. Ответы изменяющих команд выводятся после успешной записи файла.

## Формат файла

```text
M numbers 10 20 30
F items 1 2 3
L list1 4 5 6
Q tasks 100 200
S history 20 10
```

Первое число стека — вершина. Пустая структура записывается только типом и именем. Новый файл создаётся после первого успешного добавления. После удаления последнего элемента имя остаётся в файле.

При запуске читаются все строки, но восстанавливается только выбранный контейнер. При изменении заменяется его строка, затем весь файл перезаписывается. Другие строки сохраняются как текст.

Параллельная запись несколькими процессами не поддерживается. Файл записывается напрямую, без временной копии и восстановления при сбое. Строки других структур полностью не проверяются, поэтому отсутствие дерева не означает автоматического удаления чужих строк из существующего файла.

## Функции интерфейса

- parseArguments — проверяет os.Args и извлекает файл и текст запроса.
- argumentCount — определяет количество чисел для команды; неизвестная команда даёт -1.
- parseQuery — разбирает команду и имя, проверяет число аргументов, преобразует числа и обрабатывает REVERSE.
- canCreate — определяет команды добавления.
- readFile — читает файл, находит выбранное имя, проверяет тип и возвращает исходные строки, выбранные числа, позицию и тип.
- executeCommand — выбирает пакет структуры и вызывает его Execute.
- structureToString — создаёт файловую строку.
- writeFile — заменяет либо добавляет строку и записывает файл.
- printResult — выводит ответ, либо OK для изменения без другого результата.
- run — организует всю последовательность и возвращает ошибку при неудаче.
- main — вызывает run, печатает ошибку в stderr и завершает программу с кодом 1. Успех завершается кодом 0.

## Пример

```bash
./dbms --file file.data --query 'MPUSH numbers 10'
./dbms --file file.data --query 'MPUSH numbers 30'
./dbms --file file.data --query 'MPUSHINDEX numbers 1 20'
./dbms --file file.data --query 'PRINT numbers'
./dbms --file file.data --query 'MGET numbers 1'

./dbms --file file.data --query 'SPUSH history 100'
./dbms --file file.data --query 'SPUSH history 200'
./dbms --file file.data --query 'SPOP history'

./dbms --file file.data --query 'QPUSH tasks 10'
./dbms --file file.data --query 'QPUSH tasks 20'
./dbms --file file.data --query 'QPOP tasks'
```

В архиве только исходники, README и тесты. Исполняемый файл собирается локально. Во всех .go файлах отступы заменены на 2 пробела и нет комментариев. Стандартный gofmt обычно возвращает табы — это нормально для Go, но повторное его применение изменит запрошенное форматирование.
